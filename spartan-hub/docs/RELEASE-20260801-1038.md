## 本版关键修复

### 1. 端到端 BUG 修复（v0.3.1 - v0.3.3，3 个 commit）

| Commit | Bug | 修复 |
|--------|-----|------|
| `b1a0227` | refreshFromBackend 破坏性清空 + 静默吞错 | 改为构建新对象 + 失败保留旧值 + 失败计数 + UI 警告条 |
| `95edd34` | 后端 SQL 漏查 `member_id` 字段 | SQL 加 `member_id AS memberId` |
| `8bfc4f0` | 后端 `summary` 接口返回数字 `paidStatus` 而非字符串 | 加 `splitRowSummary()` 转换函数，与 `splitRow()` 一致 |

**教训**：每个路由的返回值格式必须一致，前端依赖隐式约定。修一个 bug 必须用 `node scripts/debug-dashboard.mjs` 端到端验证，不能只看 API 单点。

### 2. 数据保护机制（v0.3.4，1 个 commit）

| 文件 | 作用 |
|------|------|
| `server/scripts/reset.js` | reset 前**强制自动备份**当前 db 到 `data/backup/spartan.db.YYYY-MM-DD_HH-mm-ss.bak`，备份失败时 3 秒延迟让用户决定 |
| `server/scripts/restore.sh` | **新增**备份管理工具：`backup` / `list` / `restore` / `clean` |
| `docs/DEV-RULES.md` | **新增**开发规则文档：明确禁止 `rm -f spartan.db` 等破坏性操作 |
| `docs/CHANGELOG.md` | 新增 v0.3.4 条目记录事故和防护 |

**触发事件**：v0.3.2 / v0.3.3 修 bug 时连续 `rm -f spartan.db` 两次，把用户测试期间的真实数据**全部清空**。这次修复是直接的纠错。

## 部署步骤

```bash
# 1. 上传包
scp dist/spartan-hub-20260801-1038.tar.gz root@spartanultra.allenboard.cn:/tmp/

# 2. SSH 到生产
ssh root@spartanultra.allenboard.cn

# 3. 备份当前
cd /var/lib/spartan
cp -r data data.bak-$(date +%Y%m%d)

# 4. 部署
cd /var/lib/spartan/server
systemctl stop spartan-hub
cd /var/lib/spartan
tar -xzf /tmp/spartan-hub-20260801-1038.tar.gz --strip-components=1
cd server
sudo -u spartan npm ci --omit=dev
systemctl start spartan-hub

# 5. 验证
curl -s http://127.0.0.1:3000/healthz
```

## 风险与回滚

| 风险 | 等级 | 缓解 |
|------|------|------|
| **生产数据丢失** | 🟢 极低 | reset 自动备份 + restore.sh 工具 |
| 旧版客户端缓存 | 🟢 低 | 强刷 + Cache-Control |
| 服务启动失败 | 🟡 中 | systemd 自动重启 |
| 浏览器缓存 | 🟢 低 | 部署后 Ctrl+Shift+R |

