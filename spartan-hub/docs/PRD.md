## 1. 项目背景与目标

### 1.1 项目背景

SpartanUltra 是一次超兽赛事（Spartan Ultra）的团队参与项目，团队 7 人参赛，其中 6 名为运动员（m1–m6），1 名为领队/管理员（a1 / admin）。

赛事基本信息：
- **赛事名称**：Spartan Ultra 2026（超级野兽赛）
- **赛事距离**：约 21 km（超兽赛道，39–72 障碍为 1–38 的重复段，涉水障碍仅第一圈出现）
- **关门时间**：07:15 出发，各补给站/水站关门时间如下（以出发时间为基准）：

| 站点 | 距起点 | 关门时间 |
|---|---|---|
| 水站 1 / CP1 | 5.6 km | 08:45 |
| 水站 2 / CP2 | 10.3 km | 10:30 |
| 水站 3 / CP3 | 14.6 km | 12:15 |
| 水站 4 / CP4 | 19.2 km | 14:00 |
| 终点 | 21 km | 15:00 |

- **出发批次**：07:15 起跑
- **精英组 / 年龄段组**：本团队参加年龄段组，不标注精英组信息

### 1.2 项目目标

为团队搭建一个轻量 Web 应用，实现以下目标：

1. **信息公开**：赛事信息（赛道地形、障碍一览、水站/补给站、关门时间）无需登录即可浏览
2. **团队协同**：成员可查看/管理自己的费用清单、装备待办、行程任务
3. **统一管理**：管理员统一管理所有成员信息、费用审核、装备统筹、公告发布
4. **轻量部署**：运行在 2C2G 腾讯云服务器上（`spartanultra.allenboard.cn`），支持 HTTPS

## 4. 功能详情

### 4.1 公开信息模块

#### 4.1.1 首页 / 公告

- **入口**：打开 `https://spartanultra.allenboard.cn/` 即见
- **内容**：
  - 赛事倒计时
  - 最新公告（管理员发布，支持置顶）
  - 快捷导航入口
- **验收条件**：公告列表展示，支持管理员在后台增删改

#### 4.1.2 赛道预览

- **内容**：
  - 赛道地形图（高清，静态资源，支持下载）
  - 分段距离标注
  - 各 CP 点距离/关门时间叠加展示
- **验收条件**：图片清晰，下载按钮可用

#### 4.1.3 障碍一览

- **内容**：全部 72 个障碍列表（含中英文对照）
- **规则说明**：
  - 超级野兽赛全程约 21 km，共 72 个障碍
  - 39–72 号障碍与 1–38 号障碍相同（涉水障碍除外，涉水仅第一圈有）
  - 部分障碍需 Burpee 惩罚替代通过
- **验收条件**：障碍中文名称准确，规则说明清晰

#### 4.1.4 水站 / 补给站

- **内容**：补给站和水站详情，含：
  - 位置（距离/CP点）
  - 关门时间（结合 07:15 出发基准）
  - 服务内容（参考素材图片：水、功能饮料、香蕉、能量胶等）
- **验收条件**：关门时间与赛事规则一致

#### 4.1.5 比赛攻略

- **内容**：参考公众号文章整理的比赛技巧、注意事项等
- **验收条件**：图文结合，内容完整

### 4.2 成员功能模块

#### 4.2.1 登录（v0.3）

- **方式**：输入姓名全拼（小写），仅校验用户存在性，无密码
- **示例**：`chener` / `zhangyi`
- **会话**：JWT Token，存于 HttpOnly Cookie，有效期 8 小时
- **前端**：调 `POST /api/v1/auth/login`（不读内存校验），失败 alert
- **启动校验**：`GET /api/v1/auth/me` 验证 token，过期/撤销自动清登录态
- **验收条件**：用户名正确则登录成功；不存在则 alert"用户不存在"

#### 4.2.2 行程预览

- **内容**：成员个人待办任务清单（如装备准备、体能训练、出行安排等）
- **操作**：成员可查看/添加/标记完成/删除个人任务
- **验收条件**：任务 CRUD 正常，数据归属正确

#### 4.2.3 费用清单

- **查看范围**：仅限本人被分摊的费用记录及汇总
- **展示内容**：
  - 本人待支付金额 / 已支付金额
  - 每条费用记录（来源大项名称、分摊金额、状态）
  - 当前总欠款 / 已结清
- **操作**：无新增权限，费用由管理员录入和分配
- **验收条件**：数据与管理员端一致；汇总金额计算准确

#### 4.2.4 物资管理（v0.3）

- **内容**：成员个人装备清单（装备名 + 二态确认：未确认 / 已确认）
- **操作**：成员点击卡片切换状态（未确认 ↔ 已确认）
- **真源**：服务端 SQLite（`gear_status` 表），前端只是视图缓存
- **验收条件**：
  - 个人数据隔离（仅本人或 admin 可读写）
  - 切换实时同步到团队就位率
  - 跨设备打开能看到最新状态（不再被 localStorage 旧数据覆盖）
  - 写失败必须 alert 用户

### 4.3 管理员功能模块

> 以下功能仅 `admin` 用户可用。

#### 4.3.1 公告管理

- 新增 / 编辑 / 删除赛事公告，支持置顶
- 验收条件：增删改查正常，置顶排序正确

#### 4.3.2 成员管理（v0.3 架构级）

- 查看所有成员（不限 7 名）基础信息
- **新增** / **编辑** / **删除** 成员账号
- 删除为**软删除 + 级联归档**：
  - 成员账号置 `archived_at`
  - 关联 `tasks` 一并 `archived_at`（级联）
  - `gear_status` 仅更新 `updated_at`（status 0/1 已能表示"未确认"）
  - `expense_splits` **保留**（便于历史查询与审计）
- 所有写操作写 `audit_log`：`member.create` / `member.update` / `member.archive`
- 验收条件：增删改查正常；删除不影响费用历史；写失败必须 alert 不静默吞

#### 4.3.3 费用管理

管理员以**大项记账 + 分摊**为核心模式管理所有费用：

**大项（expense_items）**
- 管理员新增一个大项（如"上海–香港机票"）
- 填写：大项名称、总金额（元）、支付状态（待付/已付）
- 大项由管理员全额记录，不涉及成员直接申报

**分摊（expense_splits）**
- 一个大项可挂多条分摊记录，指定：
  - 目标成员（全选或部分）
  - 该成员的分摊金额（可均摊也可手动指定）
- 例：机票总价 ¥3000，指定 6 人均摊，每人 ¥500
- 分摊金额之和允许 ≤ 总金额（剩余由管理员自担或留空）

**成员费用视图**
- 每位成员可见自己被分摊到的费用及汇总
- 成员可在"费用清单"页面标记某笔分摊为"已支付"（线下自结），管理员确认后核销

**管理员视图**
- 总览：总支出、各成员欠款/已付汇总
- 列表：全部大项及分摊明细
- 支持按成员/大项类型/支付状态筛选

**验收条件**：
- 大项可增删改查；分摊支持均摊一键计算和手动指定
- 成员只能看到自己的分摊记录，无法伪造
- 总支出 = 各成员已付 + 各成员待付 + 未分配余额，等式平衡
- 管理员可一键导出费用汇总表（CSV）

#### 4.3.4 物资统筹

- 查看所有成员装备准备状态
- 验收条件：可按成员 / 状态筛选

#### 4.3.5 任务管理

- 为任意成员分配/删除/完成行程任务
- 验收条件：跨成员任务分配正常

## 5. 边界与排除项

### 5.1 本次不做

| 排除项 | 说明 |
|---|---|
| 密码登录 | 成员无密码，全拼校验即登录 |
| 多语言 | 仅中文界面 |
| 移动端原生 App | 仅响应式 Web |
| 实时聊天 | 无 |
| 报名系统 | 无，成员固定 |
| 支付网关 | 无，在线费用仅做记录，不实际收款 |
| 邮件 / 短信通知 | 无 |
| 数据导出（Excel/PDF） | 暂不考虑 |
| OAuth / 第三方登录 | 不做 |

### 5.2 成功标准

- 所有公开信息页面无需登录即可访问
- 成员登录后仅能操作自己的数据
- admin 可完成所有管理操作
- 页面加载时间 < 2s（2C2G 环境下）
- HTTPS 证书有效，TLS 1.2+
- 部署包可在腾讯云一键部署

## 6. 非功能性需求

### 6.1 技术栈

| 层次 | 技术选型 |
|---|---|
| 前端 | 原生 HTML + CSS + JavaScript（无框架依赖，便于部署） |
| 后端 | Node.js + Express |
| 数据库 | SQLite（WAL 模式，单 PM2 worker `-i 1`） |
| 部署环境 | Ubuntu 22.04，2C2G 腾讯云 |
| 域名 | `spartanultra.allenboard.cn` |
| HTTPS | 已有 TLS 证书，Nginx 终止 |

### 6.2 性能目标

- 页面首屏加载 < 1.5s（未缓存）
- API 响应时间 < 200ms
- 并发支持 ≥ 10 用户同时访问

### 6.3 安全要求

- JWT 存储于 HttpOnly Cookie（防 XSS）
- 管理员路由中间件鉴权
- SQL 参数化查询（防注入）
- 不在前端暴露敏感数据

### 6.4 可用性

- 数据库每日凌晨 02:00 自动备份（`crontab` + `sqlite3 .dump`）
- 备份文件保留 7 天
