## 三、API 变更（新接口或破坏性变更）

### 新增 API

| Method | Path | 说明 |
|--------|------|------|
| POST | `/api/v1/members` | 新增成员（已有，上版已加） |
| PATCH | `/api/v1/members/:id` | 编辑成员（已有） |
| DELETE | `/api/v1/members/:id` | 软删除+级联归档（**v0.3 新增级联**） |
| GET | `/api/v1/gear/progress` | 团队装备就位率（v0.2 新增） |
| GET | `/api/v1/admin/audit` | 审计日志（v0.2 新增） |

### 行为变更

| 端点 | 旧行为 | 新行为 |
|------|--------|--------|
| `DELETE /members/:id` | 只 `archived_at = ?` | + `tasks.archived_at = ?` + `gear_status.updated_at = ?` + audit_log |
| `GET /members` | 7 名（按 username 排序） | 7 名（按 id 排序） |
| `GET /announcements` | 3 条（按时间） | 3 条（按 `id DESC`） |

### 破坏性变更

- **member ID 变了**：从 chener/zhangyi 等变成 kongxiangliang/allen 等
  - 影响：smoke 测试 / 任何硬编码 `m1` 之外 ID 的代码
  - 缓解：smoke.js 已更新

- **localStorage 不再缓存业务数据**：
  - 影响：用户首次访问会丢失旧 localStorage 中的"假数据"
  - 缓解：v0.3 自动清旧缓存

- **数据真源切换**：从 localStorage → 后端 SQLite
  - 影响：所有"前端模拟"的写操作不再生效
  - 缓解：所有写操作已改为调 API

## 四、部署步骤

### 生产环境升级（推荐流程）

```bash
# 1. 备份
cp /var/lib/spartan/data/spartan.db /var/lib/spartan/data/spartan.db.bak-$(date +%Y%m%d)
cd /var/lib/spartan/data && tar czf spartan.db.full.bak-$(date +%Y%m%d).tar.gz spartan.db*

# 2. 下载新包（如服务器在国外，先传到 /tmp）
scp dist/spartan-hub-20260731-2244.tar.gz root@<server>:/tmp/

# 3. SSH 到服务器
ssh root@<server>

# 4. 停服务 + 解压新包（不会覆盖 data/）
cd /var/lib/spartan/server
systemctl stop spartan-hub
cd /var/lib/spartan
tar -xzf /tmp/spartan-hub-20260731-2244.tar.gz --strip-components=1
cd server

# 5. 装新依赖
sudo -u spartan npm ci --omit=dev

# 6. 启动
systemctl start spartan-hub
systemctl status spartan-hub

# 7. 验证
curl -s http://127.0.0.1:3000/healthz
```

### 数据初始化（生产必做）

⚠️ **重要**：本版种子数据从旧 6 人改为 CSV 7 人，**生产库需要执行 seed 才能应用新数据**。

```bash
# 启动服务后，远程调 init + seed（注意：seed 是部分幂等，
# 但 members 用 INSERT OR IGNORE，如果生产已有不同 ID 的成员，
# 不会被新数据替换。需要 reset 才能完全换）

# 方式 1：API 调用（推荐）
# 用 admin 登录后通过 admin UI 操作

# 方式 2：直接 seed 脚本（首次部署适用）
cd /var/lib/spartan/server
sudo -u spartan npm run db:seed

# 方式 3：完全重置（慎用！会清空生产数据）
sudo -u spartan npm run db:reset -- --force
# 输入 DELETE 确认
```
